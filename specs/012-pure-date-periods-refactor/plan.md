# Implementation Plan: Pure Date-Based Periods and Accounting Dates

**Branch**: `012-pure-date-periods-refactor` | **Date**: 2026-07-03 | **Spec**: [spec.md](file:///Users/ale/dev/sistema-contable/specs/012-pure-date-periods-refactor/spec.md)

**Input**: Feature specification from `/specs/012-pure-date-periods-refactor/spec.md`

## Summary

Refactor the dates and periods system to use PostgreSQL `DATE` types (represented as `YYYY-MM-DD` strings in NestJS and Next.js layers) instead of `TIMESTAMPTZ` (JS `Date` objects). This ensures timezone immunity for financial reporting and period locking across Paraguay and global timezone boundary offsets, keeping audit timestamps separate in a `createdAt` (`TIMESTAMPTZ`) column.

## Technical Context

**Language/Version**: Node.js v20+, TypeScript v5.3

**Primary Dependencies**: NestJS v11, Next.js v14, TypeORM v0.3, Zod v3.23

**Storage**: PostgreSQL

**Testing**: Jest (backend unit/integration tests)

**Target Platform**: Web application (Next.js client and NestJS API server)

**Project Type**: Monorepo Web Application

**Performance Goals**: String-based range comparisons for period locking validation execute in <1ms of application CPU.

**Constraints**: Timezone-agnostic reporting aggregations ignore hour/minute/second/offset components completely.
